# Every step of tools/verify.sh, one per line: the step's name, its CI group, and `slow` when
# `tools/verify.sh --quick` leaves it out. Keep the lines sorted by name (two pull requests that
# each add a check then touch different lines). tools/verify.sh reads its step lists from this
# file and runs the steps in this order; tools/ci_tier.py reads it and picks the groups a pull
# request runs from the paths it changed; pushes to main run every group but `local`.
#
#   quick      no map needed, not even the sector split (game/map/index.json): the quick job has
#              only what is committed; every code and content change (~8 min together)
#   smoke      the prebuilt city (the phone's path) and the short map checks (~8 min after the bake)
#   roads      road rules, the runtime drive and the runtime water check (full set only)
#   ground     drape and ground (full set only)
#   landmarks  the landmark check (joins a landmark change; full set otherwise)
#   runs       the runtime game runs (full set only; each rebuilds the city, ~7 min in CI)
#   local      not in CI: the long autopilot runs, the soaks and the streaming walk, for the Mac's
#              tools/verify.sh. A step moves into a CI group when it is worth its minutes there.
#
# A new check: add its line here and its case in tools/verify.sh. `python3 -I tools/ci_tier.py
# --check` (CI, every pull request) fails when a step has a case and no line, or a line and no case.
