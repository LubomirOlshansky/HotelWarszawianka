# Systems: who owns what

Every script in `game/scripts/` by system. The city's AI (traffic, police, people) has its own page,
[city-ai.md](city-ai.md); its scripts are listed there, not here. `tools/check_architecture.py`
fails if a script is in neither page, so add a row when you add a file.

"Owner" is the one script that makes a decision. Others call it; they don't copy it.

## 1. Composition and lifecycle

| Script | Owns |
| --- | --- |
| `main.gd` | The composition root. Takes its flags from `dev_flags.gd` (`flags.NAME`); in a test run it also calls the test-only functions in `dev_harness.gd` (`harness.NAME`, each call behind `harness != null`). It loads settings and save, shows the title, builds the city and every system (`_build_*`), runs the frame (`_process`), routes input, decides what may start (`_free_block`). |
| `boot.gd` | **The boot scene** (`boot.tscn`, the project's main scene; TD-15): the first thing the engine loads. It starts the error trap (a debug build's; a release build has none). In a player's launch (no flags: every release build) it puts the title up in the first frames and loads `main.tscn`, which pulls in every other script, on a thread behind it; with flags it loads the game's scene at once (`player_launch`; `--boot` asks for the player's way). The game's scene then takes its place, and `main.gd` takes over the title and the trap (`take_title`, `take_trap`). If the game's scene does not load, the title says so. Its preloads are a short fixed list (`check_boot`). `wait_frame` paces a frame spent waiting for a thread under the title when there is no display (its own wait and `main.gd`'s two), so a headless run counts those waits in frames as a screen does. |
| `release.gd` | Release builds read no command-line flags. |
| `dev_harness.gd` | **The test-only functions** (TD-4 a2): the bench's frame and view census, the soak and the passes, the cam, ram, water, tram, teleport and quest-quit tests, the line-up, the contact log, `--clicks`, the shots and `--stops`, and the `--egg` rigs, with their own state. main.gd loads it in `_ready` once both parsers have run, only when `flags.wants_harness()` is true: one of the test flags that run its code is on. `--nosave` alone, every other flag and a release build (no flags) play with no harness. It reaches the game as `m.NAME`. main.gd calls it from the same places as before, each one a single statement behind `if harness != null: `, so a missing harness never ends the app (TD-21); `check_dev_flags` holds both. |
| `dev_flags.gd` | **The command-line flags** (TD-4 a): `parse()` reads a debug run's flags once, first thing in main.gd's `_ready`, and `parse_stream()` the streaming ones after the error trap starts; main.gd reads each value as `flags.NAME`. A value the game also changes later (the start spot and heading, the camera's yaw, pitch and zoom, the soak's leg, `police_opts` ...) stays main's own: the parser writes it as `m.NAME`, and its doc comment in main.gd says so. In a release build the list is empty (`release.gd`), so every value keeps its default. Check `check_dev_flags` (verify step `devflags`): no script but this one sets a flag's value, main's own are documented, main.gd reads no flag itself. |
| `error_trap.gd` | **The error trap**: a `Logger` that keeps the kinds of error with counts, places and what the game was doing, the last printed lines, and the session file whose end mark shows whether the last session closed by itself. `report()` is what Settings → RAPORT copies. The file, the button and the after-crash note are a debug build's (our own test runs); a release build has no trap at all (`ErrorTrap.make` gives none: testers' builds run none of it). `boot.gd` starts it and `main.gd` takes it over (`_trap_start`), marks it when the app goes to the background and refreshes its context once a second (`_trap_frame`). |
| `play_stats.gd` | **The beta's anonymous play stats** (docs/STATS.md, F 2026-11-15): the one script that knows PostHog (`game/addons/posthog`, EU Cloud). `main.gd` builds it (`_build_play_stats`), hands it the systems once (`watch`) and calls `begin`, `pause` and `resume`; it listens to their signals (activities.gd `run_started`/`run_ended`, police, first10, districts, eggs, garage, heli, radio, the settings panel) and sends only events on its white list (`EVENTS`, slugs only). Sends only from a release build with a save, the setting on (Settings → Dźwięk, key `stats`) and the token file `data/stats_key.json` (gitignored); `--stats=log` prints instead (check `stats`). A new counted event is a line in `EVENTS` and a listener here, never a PostHog call elsewhere. |
| `load_yield.gd` | `LoadYield.tick(step)`: lets one frame through during the long build so the loading bar moves. Every new `_build_*` step calls it. |
| `pause_reasons.gd` | **The game's pause** (TD-20): the reasons that hold the game paused (the loading bar, the settings card, the full map, the garage card). `hold(reason)`, `release(reason)`, `release_all()`; the tree is paused while any reason is held, so a card that closes does not start the game under one still up. `main.gd` owns the one instance (`_pause`); no other script writes the tree's pause (`check_pause`). |
| `title.gd` | The title screen, language pick, loading bar. The boot scene puts it up under the root and `main.gd` takes it over (a run with flags makes its own). It loads before the game does, so what it preloads is on `check_boot`'s list. |
| `credits.gd` | Credits and licences screen. |
| `bench.gd` | Frame cost sampling for `--bench`, `--probe` and the phone's BENCH card. |
| `debug_roads.gd` | `--debug-roads` overlay (Debug Draw add-on). |

## 2. World: the map and what stands on it

| Script | Owns |
| --- | --- |
| `map_builder.gd` | The city from map data: terrain, roads, markings, rails, buildings, trees, colliders, the height, roof and picking grids. The global map index (heights, decks, tunnels, water test). Walls, fences, hedges and guard rails: its `barriers` (`city_barriers.gd`). |
| `sector_streamer.gd` | 512 m sectors streamed round the camera (prebuilt `.scn` or built at runtime). |
| `solidity.gd` | **The solid classes** (the city objects plan, step 1): the class list every collider face is filed under (`building`, `lod2`, `fence`, `hedge`, `wall`, `pier`, `parked`, `landmark`, `edge`, ...) and the answer each gets (H, S, P, R, G; all H today), read once from `game/data/object_palette.json`, the one source; also the palette's barrier types (step 2: `types`, `type_row`) and, W2 of the walls look, its `looks` rows (`looks`, `look_row`: one per barrier type `ty`) and the key `barrier_look` (`barrier_look`, `set_barrier_look` for `--barriers=`). Pure and static. `map_builder.gd` `_solid(class, faces)` files the faces, one `Solid_<class>` body per class per sector with meta `solid`; the dressing scripts' bodies carry the same meta (`check_solids`). |
| `city_barriers.gd` | **The wall builder** (the city objects plan, step 2): walls, fences, hedges, rails and guard rails (the `lines`, `citywalls` and `guards` of the map data), drawn into the sector's building surface and their colliders filed through `map._solid(class, faces)`; the rules that pick a line's look (stairs, islands, the Palace's grounds, the street passes' overrides) and its class (`barrier_class`). The looks are the palette's barrier types (`game/data/object_palette.json` "types", read through `solidity.gd` `types` / `type_row`). W2 of the walls look: when `solidity.gd` `barrier_look()` is not `classic`, a line whose chain ends generic is drawn from its type's `looks` row (`_typed`: height from `h`, `hs` or the row, colour or a stable `alt`; `slab` through `wall_along`, `rail` as thin posts and rails, `rail_lite_along`, colliding as `railing_along`), with the same soft lines; under `classic` (the default) nothing of it runs. W4: under `panels` the rows marked `panel` are cut into 2 m panel pieces instead (`panel_along`: no city-mesh triangles, the typed colliders and soft lines; the pieces per 512 m tile in `panel_tiles`, which `map_builder.gd` `_build_panels` turns into each sector's `Panels` MultiMesh in `panel.gdshader`). W7: under `typed` and `panels` a heavy or low slab row is shaped geometry in the city mesh, the heavy kit (`wall_kit`: foot band, bays a shade apart, cap or pale band, piers and proud posts with one at each end of a run, a parapet's rail, a stone wall's top rail over water or a drop), colliding as `wall_along`, face for face; `bars_pier` gets its plinth and piers (`_pier_fence_kit`), each pier a diamond collider (class `wall`) on a soft line. A RefCounted the map makes once (`map_builder.gd` `barriers`), reaching the terrain, decks and surface helpers through the map, as `landmarks.gd` does; the map's own structures draw their rails with its `railing_along`. |
| `wall_marks.gd` | **Marks on walls** (W9 of the walls look): under barrier_look `typed` and `panels`, `city_barriers.gd` calls it per heavy slab line and hoarding: graffiti, stain and ivy colour quads in the city mesh, and slogan and banner quads (words from `game/data/wall_marks.json` drawn with `pixel_font.gd` into one atlas) that `map_builder.gd` `_build_marks` turns into one `Slogans` MeshInstance3D per sector in `wall_mark.gdshader` (`marks_material`, which `main.gd` holes and ghosts with the building material). Places are a hash of the line id and metres, clear of W8's gaps, gate posts and leaves; a district's slogans only in its `areas`; no banners on a hoarding drawn as panels; numbers are the palette's `marks` table (`solidity.gd` `marks_table`). Checked by `check_barrier_look` case 10. |
| `contact_log.gd` | **The contact log** (the city objects plan, step 3): one line per contact episode of the car (where, the `solid` class of what it touched or `traffic` / `tram` / `train`, the speed in and the lowest in the next second, the angle, the street, the flags `dead_stop`, `unstick`, `tow`) and one per street leg (metres, seconds, time at speed). Pure: its owner calls `observe(car, dt)` once a physics frame before the car's step, so the check and the game write the same lines; it changes nothing. Owners: `check_lane_drive.gd` (`--contacts=`, `--driver=sloppy`, `--set=A`) and `main.gd` (`--contacts=FILE`, a debug run's flag). `tools/drive_report.py` turns the files into the per-street table and `tools/drive_baseline.json` |
| `soft_things.gd` | **The soft things** (the city objects plan, step 7): the S fences and hedges (the bake's `sc`) have no collider; the builder (`city_barriers.gd`) files their segments in the sector root's `soft` meta instead (both city paths; whole city on `--monolithic`), and this node breaks them when the car drives through: an 8 m cell hash per sector, the car's box swept from frame to frame (only over 2 m/s, with a collision mask, on the line's level), a cost per panel from `solidity.gd` (fence 6 %, hedge 10 % of the speed, at most 15 % in 0.5 s; grinding under 15 deg costs 3 %/s and nudges the car out), signals `broke` and `repaired`, `is_broken`, `repair_near`, `reset`. Broken panels are remembered (at most 600) and stand again by rule B: over 150 m away, out of view, and 10 min or a dawn after they fell. No physics bodies: it scales `car.vel` after the car's step (physics priority 100). Made by `main.gd` `_build_soft_things`, fed by the streamer's `sector_ready` (a sector leaving the tree takes its lines with it); `main.gd` `_on_soft_broke` plays the sound (`sfx.gd` smash rows), the debris burst (one pooled GPUParticles3D), `Access.buzz`, the bubble (`dialogue.json` "smash") and counts the wallet's `smash_*`. `--no-soft` puts their colliders back (the faces equal main's). Checked by `check_soft_things`; contacts are `soft` lines in `contact_log.gd`. Step 8a: the parked cars too. The builder files their colliders as ever (`Solid_parked`, so the default, hard, is the build itself) and their boxes in the sector root's `soft_cars` meta (`map_builder.gd` `soft_cars_data`, both paths; a car by a landmark in its "guard" part, kept hard); swept, `cars_hard` turns `Solid_parked` off (layer 0) in an 8 m hash of their bays; the car's box where it is and where this frame takes it is tested against them, a push (`solidity.gd` `PUSH_*`: the player keeps 1 - 0.25 |cos| of its speed, the car takes 0.6 of the speed into its face and a small spin, slides with 6 m/s² friction, one `cast_motion` clamping it at a wall, a car it meets pushed on in turn) or, when it cannot move (the slide clamped under 0.5 m), a `parked` box collider while the player is near so `car.gd` answers it as a wall with the preset's rules; the lane rule (`graph`, `corridor_segments`, `in_corridor`) never lets one rest in a lane (shortened, lengthened, or `towed` and hidden out of view). The MultiMesh instance follows (the tile's node carries `map_builder.PARKED_TILE`); a pushed car is remembered like a panel and goes back to its bay by rule B. Signals `pushed`, `car_returned`; `main.gd` `_on_car_pushed` plays `smash_car`, buzzes, counts the wallet's `pushed_cars` and now and then says a `dialogue.json` "parked_push" line. The one settings switch (Łamliwe płoty) and `--soft` / `--no-soft` cover the cars too. |
| `panel_states.gd` | **The broken panels shown** (W6 of the walls look, docs/design/walls-true-to-life.md 7): the only writer of a panel's state in the sectors' `Panels` MultiMeshes (W4, the `panels` look). `main.gd` makes it with `soft_things.gd` and connects `broke` (the panel's pieces, found through the sector root's `panels` meta, get their row's `broken` state in the custom data: 1 down (and `flat`) with the box laid flat on the far side of the hit, 2 torn, 3 stub, 4 gap (W5), 5 a wood row's gap, its two boards laid down (W5); `panel.gdshader` draws them) and `repaired` (the baked transform and custom data back, float for float); `_on_sector_ready` calls `add_sector`, which shows a returning sector's broken panels again (`soft_things.is_broken`). A tile's buffer is read once, on its first write (on a RenderingDevice asynchronously, the writes two frames later, then one instance's floats each; else through the MultiMesh). Does nothing without `Panels` (classic, typed) or with the soft switch off (nothing breaks). Checked by `check_panel_states`. |
| `collide_rules.gd` | **The collision answer** (the city objects plan, step 6; docs/design/drivable-city-build.md item 2): the car's answer to a contact as numbers, `answer(preset, profile, speed, angle, class)` -> keep along the wall, bounce, the nose's turn rate, the head-on kick; `car_keep` (traffic hit as a rear-end, a side swipe or a T-bone), `shove_side` (how far a hit traffic car slides off its line), `ghost_push_time`. Presets `v1` (today's answer written down; car.gd runs its own block for it), `soft`, `mid`, `firm` (a graze keeps 97 / 90 / 80 %), picked by `--collide=` (main.gd; the default stays v1 until F's phone A/B). Pure and static; `car.gd` `_wall_answer` applies it, `traffic.gd` `_shove` asks it; `check_collide_rules` proves v1 is today's car and the car applies the table. |
| `collider_view.gd` | **The collider view** (the city objects plan, step 4): `--colliders`, a debug run's flag (`dev_flags.gd`), skins every collider that carries a solid class in the colour of its class's planned answer (`solidity.gd` `planned`: hard red, smash yellow, push blue, ride green; the invisible pocket walls magenta), on both city paths as the sectors stream in.
